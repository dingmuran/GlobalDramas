# Global Dramas 三角色业务平台

- 日期：2026-10-08
- 状态：本地业务版已实现（外部平台接入待提供账号、密钥）
- 用户需求：完成内容、策略、会员、用户、订单、广告、财务、数据、管理九类业务的前后端，以及带中文注释的 PostgreSQL 数据表和字段。
- 三种角色：观众端、版权方/制片方、超级管理员。
- 页面范围：观众发现/追剧/收藏/钱包订单；版权方工作台/剧集/数据/收益；管理员总览/审核/用户机构/平台财务，扩展九类后台功能。
- 约束：真实数据库数据；无演示记录；权限与数据范围在后端执行；支付、平台订阅、广告和媒体处理外部回调接口需独立验证接入。
- 实现位置：server/plugin/dramas 与 webAdmin/src/plugin/dramas。

- 实现结果：三种角色、21个业务页面、13个API定义、28张PostgreSQL业务表和333个中文注释字段；真实空数据启动，没有演示账号或内容。
- 业务规则：后端所有权过滤与写字段白名单；审核后发布，授权到期自动下架；支付/退款/广告发奖/补偿/结算需要真实凭据与不同管理员双人审批；订单金额服务端计算，退款撤权；同账期同币种结算余额约束；操作审计与异常恢复；播放权限接口隐藏付费URL。
- 验证：Docker内全部插件包编译；PostgreSQL事务集成测试（含JWT/Casbin HTTP边界、越权、续费、广告奖励、结算、CSV去重、引用保护与到期下架）通过且全部回滚；Vite生产构建通过；真实Vite代理到API/PG的28资源+概览/账号冒烟通过；SQL在临时数据库成功创建28张表后删除临时库；浏览器检查总览真实空数据。数据库仍只有正式admin账号，0测试账号。

- 实际边界：没有支付/广告/平台密钥，目前提供人工核对真实凭据的内部业务流程；未进行真实扣款、退款、转账、广告播放、自动转码或平台实时订阅同步。生产媒体仍需私有存储与签名URL。
